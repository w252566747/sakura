# HTML 复制与实时筛选导出修复记录

日期：2026-11-26（JST）

## 实际修改

1. `sakura_core/cmd/CViewCommander_Clipboard.cpp`
   - 使用选区起止处的实际布局节点限定复制范围，避免把可见行序号用作完整布局链的序号。
   - 普通选区保留折叠隐藏的内容；矩形选区只复制可见行。
   - 从自动换行的中间片段开始复制时，回退扫描逻辑行首以恢复颜色状态，同时修正片段计数，避免输出选区之前的文本、行号或额外换行。
   - 选区结束在换行片段内部时，不再复制后续片段；在无下一个布局节点时安全结束。
   - 行号宽度使用对应的逻辑/完整布局行范围。普通无行号复制无需从文档开头重新计数隐藏行。
   - 保留原来的语法颜色策略和 HTML 转义函数；不展开折叠、不修改原文。
2. `sakura_core/window/CEditWnd.cpp`
   - 移除筛选结果导出时查不到新建窗口就向当前前台窗口粘贴的回退。
   - 新建窗口无法确认时，继续使用已有错误提示并将结果保留在剪贴板中。
3. 新增 `tools/tests/html-copy-standalone.cpp`、`tools/tests/run-html-copy-standalone.py`。
4. 更新开发进度文档和本记录。

修改前的目标源文件和进度文档已备份在 `/private/tmp`。原有未提交改动保留，未整理或提交混合工作区。

## 实际执行的验证

```sh
python3 tools/tests/run-html-copy-standalone.py
git diff --check
```

Python 测试脚本从当前源码提取真实的 `AppendHTMLColor` 和 `Command_COPY_COLOR_HTML` 函数体，使用 Clang C++17、`-Wall -Wextra -Werror` 和 UndefinedBehaviorSanitizer 编译后运行。文档、布局、剪贴板和颜色策略由隔离测试替身提供。

结果：

- 1,489 组原文选区对比通过，涵盖未折叠/折叠、多种自动换行宽度和不同起止位置。
- 额外的反向选择、矩形选择、CRLF、EOF、HTML 特殊字符、颜色样式和行号用例通过。
- 用修改前备份作为 `--source` 运行同一测试，跨折叠复制用例失败，复现复制截断；修复后通过。
- 源文件 UTF-8 BOM 和原有 LF 行尾保留。
- `git diff --check` 通过。
- 当前主机开启 AddressSanitizer 的测试进程以 SIGILL 退出；默认测试使用能够运行的 UndefinedBehaviorSanitizer，未声称 AddressSanitizer 通过。

检查到普通保存命令在筛选模式允许执行，仍经过原有 `Command_FILESAVE`、`CDocFileOperation::DoSaveFlow` 和 `CSaveAgent::OnSave`。最后通过 `WriteFile_From_CDocLineMgr` 写原始文档行存储，没有改成输出筛选结果缓存。
